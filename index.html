NIEVUNE E-COMMERCE V6 — CUSTOMER ACCOUNTS WHAT WAS ADDED - Complete customer login interface in the public store. - Email + password account creation. - Email confirmation flow. - Persistent sessions with automatic token refresh. - Forgot-password email and password recovery screen. - Account page with display-name editing, password change and sign out. - Favorites now require an account. - Favorites synchronize across devices through Supabase. - Favorites use local cache for immediate loading and stale-while-revalidate. - Offline favorite changes are queued and synchronized when the connection returns. - The old browser-only favorites are migrated to the first signed-in account. - The cart continues to be cached locally for fast guest shopping. - Customer accounts cannot access the product manager. If the keys are empty, the login dialog explains that the account service still needs to be connected. SUPABASE SETUP 1. Create a Supabase project. 2. Open SQL Editor and run the entire supabase-schema.sql file. 3. In Project Settings > API, copy: - Project URL - public anon key 4. Paste both values into config.js. 5. In Authentication > URL Configuration: - set Site URL to your published site URL; - add the public /store/index.html URL to Redirect URLs. 6. In Authentication > Providers > Email, keep email/password enabled. 7. Publish the updated project. CREATE THE OWNER ACCOUNT SAFELY Customer registration is public, so the first customer must NEVER automatically become the shop owner. The old claim-first-admin function has been removed. 1. Create your own account from the public store and confirm its email. 2. In Supabase SQL Editor, run this once, replacing the email: insert into public.shop_admins (user_id) select id from auth.users where email = 'YOUR_OWNER_EMAIL@example.com' on conflict (user_id) do nothing; 3. Open manage-nievune.html and sign in with the same account. 4. Regular customer accounts will be denied access by Row Level Security. CACHE BEHAVIOUR - Supabase securely persists the auth session in browser localStorage and automatically refreshes access tokens. - A non-sensitive profile snapshot is cached only to render the account button quickly while the session is being checked. - Favorite IDs are cached per user and refreshed from the database on load. - Offline favorite changes are stored in a per-user queue and retried online. - Database RLS remains the source of truth and prevents users from reading or changing another user's favorites/profile. SECURITY - Never put the Supabase service-role key in config.js. - The anon key is public by design; Row Level Security protects private rows. - Keep email confirmation enabled before production. - Add the correct production redirect URL before testing confirmation/reset.
